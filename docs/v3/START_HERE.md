# 从哪里开始

1. **不要直接修改正式线上主分支。** 将完整原始工程打包做 V2 基线，保存各版本本地存档 fixture。旧版主程序在当前会话只有用户上传的一个文件，并没有真正拿到物理和字形模块源。
2. 完成 M0：用现有模块在无头环境重放固定样本，输出 golden results。要求旧版结果逐项可复现。
3. 使用 `v3-contracts.ts` 冻结首版结构。这里是设计接口，不是实现。先定义 `Classic` 和 `Arena HP` 两套隔离的 Ruleset。
4. 用 `LegacyBattleAdapter` 包住现有 Battle，使 UI/输入和旧物理脱钩；等回归通过再实施 `DamageResolver`。
5. 完成第一关纵切：选择文字（速度/力量/HP）→ 精准发射 → 受伤/出界/转停 → 战斗结算 → 本地存档。只有这一流程完整后，才做 12 关和云存储。
6. Cloud save 使用版本号和幂等事件；排名只接受服务端验证的结果；PVP 放到最后。

完整阶段、页面合同、代码归属、规则边界、测试标准见 `MASTER_PLAN.md`。
